`[ CREATE NEW USER ]`. The `FROM THE FOUNDATION` tagline moves from the bottom
to the top (spaced down from the title card) and centered. Usernames stay
left-aligned; right-aligned, each account shows a readout — storage amount and
amount used, plus the number of violations from the Frank system.

- `hub/foundationhub/screens/login.py` — `LoginScreen` now renders all

  `N VIOLATIONS`, right-aligned via the menu's status column). An empty slot is

- Labels: `LOGIN_CREATE_SLOT`, `LOGIN_VIOLATIONS` added; the old

## 2. New account needs a restart to appear — ✅ FIXED
`LoginScreen` was load-once for the life of the greeter process, so an account
created out-of-band (root helper / another console) only showed after a device
restart. The roster now stamps `users.json` (mtime + size) and re-reads it in
`draw()` when it changes — the new account appears immediately.
`hub/foundationhub/screens/login.py` (`_maybe_reload`), covered by
`test_roster_reloads_when_registry_changes`.

### Frank violation counts (new plumbing for item 1's readout)
- `frank/frankd/violations.py` — persistent per-user counts in
  `/var/lib/frank/violations.json`; a "violation" is any finding that produced
  a user-facing reaction (warn or lockout), never a silent observation. Survives
  reboots and the daily reset (records follow the person).
- `frankd/daemon.py` increments on WARN/LOCKOUT and publishes the counts (count
  only, no detail) into the public login summary. `frankd/lockstate.write_public`
  gained a `violations` field; `hub/foundationhub/session.read_login_locks`
  reads it. Same disclosure rule as the ledger: when and how many, never why.
- Tests: `frank/tests/test_violations.py`, updated `test_lockstate.py`.

## 3. Rogue 5.4 looked like a second copy of the 1981 game — ✅ FIXED (color)
The vendored 1985 build (`rogue54`) is authentic but monochrome, so on the amber
kernel VT it was visually identical to the 1981 build — "two of the 1981 games."
Added a classic PC-Rogue color layer, applied at build time so `src/` stays
verbatim upstream:
- `vendor/rogue5.4/color/xcolor.{h,c}` (new, original to this repo) — wraps the
  four character-plotting primitives to attach a color pair per symbol (floor
  green, walls/passages amber, gold/rings/amulet yellow, potions/weapons/stairs
  cyan, scrolls white, monsters bold red, player bold white). Color rides only
  in the attribute bits, which the game masks off with `CCHAR()` when it reads
  the map back, so it can't perturb game logic.
- `vendor/rogue5.4/PKGBUILD` `prepare()` copies the layer into the build and
  wires it in (rogue.h include, `roguecolor_start()` after initscr, Makefile.in
  object/header). The Hub runs this game with `full_color` (new `Launch` flag),
  which restores the VT's stock palette so the colors land true instead of
  phosphor amber, then re-applies the phosphor palette on exit
  (`hub/foundationhub/theme.vt_stock_palette` / `vt_theme_palette`).
- The 1981 build stays monochrome on purpose — that's what keeps the two
  vintages visually distinct.

## 4. No way to exit the Rogue games — ✅ FIXED (Esc + confirm)
Both games now exit on Esc, gated by the game's own "really quit?" confirm
prompt (mirrors the existing `Q` command; scores and returns to the Hub only on
"y", falls through to the normal Esc reset on "n"). Applied at build time in
each PKGBUILD's `prepare()` — `vendor/rogue5.4` and `vendor/rogue3.6`. Save-on-
exit was not added this pass (deferred; the native quit still records the score
board as it always did).

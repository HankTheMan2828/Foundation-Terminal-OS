# Operator feedback — 2026-07-05

Second feedback batch after the first hardware runs. Login-screen rework, an
account-visibility bug, the two Rogue games (color + a way out), and dropping
NetHack. All items done this session.

## 1. Login screen rework — ✅ DONE
Vision: 8 user slots with a little spacing; an unused slot reads
`[ CREATE NEW USER ]`. The `FROM THE FOUNDATION` tagline moves from the bottom
to the top (spaced down from the title card) and centered. Usernames stay
left-aligned; right-aligned, each account shows a readout — storage amount and
amount used, plus the number of violations from the Frank system.

- `hub/foundationhub/screens/login.py` — `LoginScreen` now renders all
  `MAX_ACCOUNTS` (8) slots with a blank spacer row between each. A filled slot
  is the account (username left; tier hint + `used / allotment` storage +
  `N VIOLATIONS`, right-aligned via the menu's status column). An empty slot is
  a `[ CREATE NEW USER ]` placeholder that enters registration. Storage is
  measured with `fileops.dir_size()` over the account's data dir once per roster
  build; violations refresh live from Frank's public summary.
- Tagline: centered on the first content row, spaced under the title card; a
  registration notice takes the row just below it.
- Labels: `LOGIN_CREATE_SLOT`, `LOGIN_VIOLATIONS` added; the old
  `NEW OPERATOR REGISTRATION` / `TERMINAL AT ACCOUNT CAPACITY` rows are gone
  (their behavior is folded into the slot placeholders).
- Tests: `hub/tests/test_login_roster.py`.

## 2. New account needs a restart to appear — ✅ FIXED
`LoginScreen` was load-once for the life of the greeter process, so an account
created out-of-band (root helper / another console) only showed after a device
restart. The roster now stamps `users.json` (mtime + size) and re-reads it in
`draw()` when it changes — the new account appears immediately.
`hub/foundationhub/screens/login.py` (`_maybe_reload`), covered by
`test_roster_reloads_when_registry_changes`.

### Frank violation counts (new plumbing for item 1's readout)
- `frank/frankd/violations.py` — persistent per-user counts in
  `/var/lib/frank/violations.json`; a "violation" is any finding that produced
  a user-facing reaction (warn or lockout), never a silent observation. Survives
  reboots and the daily reset (records follow the person).
- `frankd/daemon.py` increments on WARN/LOCKOUT and publishes the counts (count
  only, no detail) into the public login summary. `frankd/lockstate.write_public`
  gained a `violations` field; `hub/foundationhub/session.read_login_locks`
  reads it. Same disclosure rule as the ledger: when and how many, never why.
- Tests: `frank/tests/test_violations.py`, updated `test_lockstate.py`.

## 3. Rogue 5.4 looked like a second copy of the 1981 game — ⤳ SUPERSEDED 2026-07-06
First attempt (this doc's original entry): a build-time color layer on the
vendored BSD rogue5.4 (`vendor/rogue5.4/color/xcolor.{h,c}` + a `full_color`
`Launch` flag / VT palette switch). The operator reviewed it against their
screenshot and it was **not right** — the screenshot is the graphical DOS/PC
Rogue (smiley player, CP437 glyphs), which the ASCII BSD rogue5.4 can't produce
by coloring alone.

**Reverted 2026-07-06.** The exact-match open-source port (roguepc) is
unlicensed and derives from the commercial Epyx PC Rogue, so it can't be baked
into the redistributable ISO. Rather than ship a monochrome rogue5.4 that just
duplicates the 1981 game, the whole color attempt and the rogue5.4 vendoring
were dropped:
- Deleted `vendor/rogue5.4/` (color layer + BSD source); removed the
  `full_color` `Launch` flag and `theme.vt_*` palette helpers; dropped `rogue5.4`
  from `install/packages.txt` and the `image/build-iso.sh` `VENDORED` list.
- **Rogue (1985) is now a downloadable skeleton** — a not-installed `rogue54`
  menu slot with a "downloadable graphical build" hint. See
  `docs/ROGUE-DOWNLOADABLE.md` for the blocker, the hooks, and the kernel-VT
  rendering constraint. The operator will wire up a real build themselves.
- The 1981 OG (`vendor/rogue3.6`) is now the only Rogue shipped.

## 4. No way to exit the Rogue games — ✅ FIXED (Esc + confirm)
Rogue exits on Esc, gated by the game's own "really quit?" confirm prompt
(mirrors the existing `Q` command; scores and returns to the Hub only on "y",
falls through to the normal Esc reset on "n"). Applied at build time in the
shipped game's `PKGBUILD` `prepare()` — `vendor/rogue3.6`. (It was also in the
now-removed `vendor/rogue5.4`; if the downloadable 1985 build lands it should
carry the same Esc gate.) Save-on-exit was not added this pass (deferred; the
native quit still records the score board as it always did).
